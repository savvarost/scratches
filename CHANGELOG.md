# История изменений

## [1.1.0]

### Хранение и настройки

- **Project Files** использует каталог `<root>/.projects/<имя>-<хеш URI>` для первой папки workspace. Проекты с одинаковыми именами и разными URI разделены; каталог нового проекта создаётся до обновления представления и не перезаписывает конфликтующий файл.
- Старые каталоги `<root>/<имя проекта>` не переносятся и остаются доступны в **All Files**. Изменение URI workspace приводит к выбору нового каталога. Без открытой папки workspace создание проектного файла недоступно.
- При отсутствии `scratches.path` файловые представления не инициализируются, а домашняя директория не используется как запасной корень. Команда **Scratches: Set Root Path** доступна в палитре, в том числе при ошибочной настройке; после исправления пути представления восстанавливаются.
- В настройке пути `~` раскрывается только в начале пути. Выбранная директория сохраняется в глобальную настройку.
- Список расширений и счётчики использования перенесены в глобальное состояние профиля VS Code. При первом обращении старый список из `<root>/.vscode/.recentFileExtension.json` импортируется с нулевыми счётчиками и остаётся на месте. Повреждённый список и символическая ссылка отклоняются; при отмене выбора расширения файл не создаётся. Расширения сортируются по частоте успешного создания файлов, при равной частоте сохраняется порядок добавления.

### Представления, поиск и сравнение

- Исправлена регистрация приветственного представления и жизненный цикл деревьев: при смене пути существующие представления получают новые корни, выделение и внутреннее состояние операций сбрасываются.
- После файловых операций обновляются все представления. Для внешних изменений добавлен общий наблюдатель корня с объединением событий и освобождением ресурсов при смене пути и завершении работы.
- Добавлен поиск буквального текста без учёта регистра по сохранённым UTF-8 файлам в каждом представлении. Действуют ограничения размера и количества файлов и результатов; бинарные, несохранённые и недоступные файлы пропускаются, поиск можно отменить.
- Добавлено сравнение двух файлов в стандартном diff VS Code: можно выбрать первый и второй файл или выделить ровно два разных файла. Команды недоступны без необходимого выбора, подсказка указана в их названиях. Выбор первого файла сбрасывается при смене корня либо обнаружении его исчезновения или замены. Команда палитры открывает последнюю пару файлов в обратном порядке.
- Добавлено сравнение scratch-файла с текстом буфера из меню файла и палитры: файл находится слева, редактируемый временный документ — справа. Поддерживаются пустой буфер и несохранённые изменения исходного документа; расширение не сохраняет историю буфера.
- Для сравнения проверяются обычные UTF-8 файлы до 10 МиБ, их расположение и идентичность; текст буфера также ограничен 10 МиБ. VS Code показывает несохранённое содержимое открытых документов, а проверка файла выполняется по сохранённому содержимому.

### Файловые операции

- Добавлены множественное выделение и пакетные Copy, Cut и Delete до 100 элементов, копирование и перенос папок между представлениями. Конфликты пропускаются без перезаписи, обработка остальных элементов продолжается, а ошибки показываются пользователю. Неудачные элементы вставки остаются для повторной попытки.
- В локальном настольном VS Code на macOS Copy и Paste экспериментально используют системный файловый буфер: поддерживаются файлы и папки, а также импорт локального списка Explorer в формате `code/file-list`. Внешняя вставка копирует; системный Cut не обещает перемещение. В других ОС и удалённых окружениях используется внутренний буфер. Формат Explorer является внутренним и может измениться.
- При копировании папок вложенные символические ссылки отклоняются; в случае ошибки частично созданная папка может остаться в месте назначения. Папку нельзя копировать или перемещать внутрь неё самой.
- Создание файла выполняется без перезаписи. Имена новых и переименованных элементов проверяются; поле переименования содержит текущее имя, а его подтверждение без изменений не выполняет файловую операцию. Если созданный файл не удалось открыть, он сохраняется и пользователь получает сообщение.
- Переименование выполняется через VS Code и обновляет открытые вкладки. Переименование и удаление отклоняются при несохранённых изменениях в файле или внутри выбранной папки; после ввода и подтверждения проверяется идентичность объекта.
- Удаление файлов и папок после подтверждения использует системную корзину. Добавлены сочетания `Cmd+Backspace` на macOS и `Ctrl+Delete` на Windows и Linux.
- Copy и Cut проверяют идентичность источника и состояние корней; замена выбранного объекта или смена корня приводит к отказу. Перед копированием и перемещением требуется сохранить изменения. При обнаружении изменения источника или частичной ошибке пользователь получает предупреждение о возможной копии в месте назначения; неудачная вставка сохраняет состояние для повтора.
- Открытые сохранённые файлы при Cut и Clear перемещаются через VS Code с обновлением вкладок. Для закрытых файлов используется жёсткая ссылка или, между файловыми системами, копирование с последующим удалением источника. Если файл изменился, был открыт во время переноса или удалить его не удалось, исходник сохраняется и копия назначения может остаться.
- Открытие файлов и копирование пути проверяют границы представления и символические ссылки. Ссылки скрыты в деревьях; корень и служебные каталоги должны быть обычными директориями. Ошибки операций отображаются пользователю.

### Очистка

- **Clear** обрабатывает файлы непосредственно в корне выбранного представления и перемещает их в его папку `trash` без перезаписи. Учитываются корректная дата в начале имени `YYYYMMDD-HHMMSS` и время изменения файла: оба должны быть не позднее начала введённой даты `YYYY-MM-DD` по UTC.
- Пока ожидается подтверждение, найденные кандидаты отмечаются красным значком в соответствующем дереве; после ответа или смены корня отметки исчезают. Это предварительный список: несохранённые, изменившиеся или конфликтующие файлы могут быть пропущены.
- Ошибка проверки кандидата отменяет составление списка. Перед переносом повторно проверяются корень и снимок файла; при смене корня операция отменяется или прекращает обработку оставшихся файлов. Результат сообщает о перемещённых и неудачных элементах; при частичной ошибке следует проверить исходный каталог и `trash`.

### Разработка и совместимость

- Минимальная версия VS Code повышена с 1.91 до 1.105. Для инструментов разработки требуется Node.js 22.13 или новее в ветке 22 либо Node.js 24 или новее.
- Обновлены зависимости разработки; `@vscode/test-cli` заменён запуском через `@vscode/test-electron` и Mocha 12. Удалено переопределение `serialize-javascript`; по умолчанию тесты запускаются в VS Code 1.105.0.
- Добавлены интеграционные тесты файловых операций и жизненного цикла, включая проверку workspace после повторного открытия. Тестовый VS Code использует отдельный временный профиль; CI настроен для Linux, macOS и Windows, а на Linux задан отдельный каталог для тестов между файловыми системами.
- Исходники тестов и скомпилированный тестовый runner исключены из устанавливаемого пакета; в манифест добавлен адрес репозитория.
- Обновлён [README](README.md), добавлены [карта расширения на русском](EXTENSION_MAP.ru.md) и [английская версия для агентов](EXTENSION_MAP.md), а также инструкции [AGENTS.ru.md](AGENTS.ru.md) и [AGENTS.md](AGENTS.md).

### Известные ограничения

- Проверка путей и последующая файловая операция не являются единой атомарной операцией; остаётся риск конкурентной подмены. Часть файловых операций остаётся синхронной.
- Используется только первая папка multi-root workspace. Нативный файловый буфер поддерживается экспериментально только в локальном настольном VS Code на macOS.
- Для локальных тестов переноса между файловыми системами нужен доступный каталог на другом томе; без него соответствующие тесты пропускаются. Состояние уязвимостей зависимостей зависит от даты проверки и требует отдельного актуального аудита.
