# Scratches для Visual Studio Code

Scratches хранит временные и экспериментальные файлы в выбранной общей директории и показывает их в панели Activity Bar. Требуется VS Code 1.105 или новее.

## Начало работы

1. Установите расширение и откройте панель **Scratches**.
2. Выберите существующую директорию хранения через **Set Root Path** в приветственном представлении, команду **Scratches: Set Root Path...** в палитре команд или настройку `scratches.path`.
3. Создайте файл кнопкой **New Scratch File**: выберите расширение (при первом использовании добавьте его через **New extension**, например `.py`) и при необходимости измените предложенное имя.

В настройке `scratches.path` можно указать домашний каталог как `~` или начать путь с `~/` (на Windows также `~\`). Символ `~` внутри имени папки сохраняется без изменений.

По умолчанию имя содержит UTC-метку времени `YYYYMMDD-HHMMSS` и выбранное расширение. Вводите расширение вместе с начальным символом `.`. Список и счётчики использования хранятся в глобальном состоянии расширения для профиля VS Code и не зависят от выбранной директории. Часто используемые расширения показываются первыми; при одинаковой частоте сохраняется порядок добавления. Использование учитывается после создания файла, если итоговое имя оканчивается выбранным расширением.

При первом обращении к списку существующий файл `<root>/.vscode/.recentFileExtension.json` импортируется с нулевыми счётчиками и остаётся на месте. При ошибке чтения или некорректном содержимом импорт не завершается: исправьте или восстановите файл и повторите попытку. Старые списки из других корневых директорий автоматически не объединяются. Состояние не синхронизируется через Settings Sync.

## Представления и операции

- **Project Files** — директория в `<root>/.projects`, определяемая полным URI первой папки workspace; доступна при открытом workspace. Проекты с одинаковыми именами папок используют разные директории. Старые каталоги `<root>/<имя проекта>` не перемещаются и остаются доступны в **All Files**; нужные файлы можно перенести вручную.
- **Shared Files** — общая директория `<root>/share`.
- **All Files** — содержимое корневой директории, включая директории проектов и общую директорию.

Без открытой папки workspace проектные файлы создать нельзя; для работы в таком окне используйте **Shared Files** или **All Files**.

Кнопка **Search File Contents** в заголовке каждого представления ищет буквальную строку без учёта регистра во вложенных файлах этого представления. Выберите результат, чтобы открыть файл на первой подходящей строке. Поиск читает сохранённое содержимое UTF-8, пропускает файлы с несохранёнными изменениями, бинарные файлы, символические ссылки и файлы больше 1 МиБ. Он останавливается после 100 найденных файлов или 10 000 элементов дерева; о пропусках и достижении ограничений сообщается. Поиск можно отменить.

В деревьях доступны создание файлов и папок, открытие, переименование, копирование пути, копирование и перемещение файлов и папок, удаление и обновление. Можно выделить до 100 элементов и выполнить Copy, Cut или Delete. Новый scratch-файл создаётся в корне выбранного представления; новая папка может создаваться внутри выбранного элемента.

Деревья автоматически обновляются при внешних изменениях в директории хранения, включая вложенные папки. VS Code может не сообщать о путях, исключённых настройкой `files.watcherExclude`, или временно приостанавливать наблюдение за удалённой директорией; в таких случаях используйте кнопку **Refresh** и при необходимости заново выберите корень.

Чтобы сравнить текстовые файлы, выберите **Select for Compare** в меню первого файла, затем **Compare with Selected (select first file)** в меню второго. Вторая команда неактивна, пока первый файл не выбран. Можно также выделить ровно два файла в одном представлении и выбрать **Compare Selected (select two files)**; при другом выделении эта команда неактивна. Различия открываются в редакторе сравнения VS Code; команда **Scratches: Swap Compared Files** в палитре открывает сравнение с обратным порядком сторон. Сравнение доступно для обычных UTF-8 файлов размером до 10 МиБ, в том числе из разных представлений. Двоичные файлы и символические ссылки отклоняются. Если файл открыт и содержит несохранённые изменения, VS Code показывает содержимое редактора; проверка типа и размера выполняется по сохранённому файлу. Снимки и история версий не создаются.

Чтобы сравнить scratch-файл с текстом из буфера, выберите **Compare with Clipboard** в меню файла или откройте файл и запустите **Scratches: Compare Active File with Clipboard** из палитры. Слева показывается файл, включая несохранённые изменения, справа — редактируемый временный документ с текстом буфера. Если буфер пуст, текст можно вставить или набрать справа вручную. Текст буфера ограничен 10 МиБ; расширение не сохраняет его в своей истории. Временный документ управляется VS Code и при необходимости может быть сохранён пользователем. Команда **Swap Compared Files** относится к сравнению двух файлов.

При пакетной вставке существующие элементы не перезаписываются: конфликтующие пропускаются, остальные обрабатываются, а результат показывается пользователю. Неудачные элементы остаются в буфере для повтора. Если выбраны папка и находящийся в ней элемент, операция применяется только к папке. При копировании папки вложенные символические ссылки отклоняются; при ошибке частично созданная папка назначения остаётся на месте, поэтому перед повтором проверьте её. Копирование и перемещение папки внутрь самой себя запрещено.

В локальном настольном VS Code на macOS команды Copy и Paste экспериментально используют системный файловый буфер: Paste принимает до 100 обычных файлов или папок, Copy помещает ссылки на выбранные элементы в буфер. Поддерживается также внутренний формат списка локальных файлов Explorer VS Code, который может измениться в будущих версиях редактора. Символические ссылки не импортируются, существующие файлы не перезаписываются. При частичной ошибке проверьте назначения перед повтором. В удалённых окружениях и на других ОС используется внутренний буфер Scratches.

Cut между представлениями Scratches сохраняет поведение перемещения. Внешние файлы из системного буфера только копируются. На macOS Cut также помещает файловую ссылку в системный буфер как Copy: вставка в другое приложение не обещает перемещение исходника.

Перед переименованием или удалением сохраните изменения в открытом файле и во всех открытых файлах внутри выбранной папки. Перед перемещением через Cut сохраните изменения в файле; Clear пропускает файлы с несохранёнными изменениями и сообщает о них. Переименование выполняется через VS Code, чтобы обновить открытые вкладки.

Чтобы удалить выбранный элемент из дерева Scratches, используйте контекстное меню **Delete** или сочетание `⌘ + Backspace` на macOS (`Ctrl + Delete` на Windows и Linux). После подтверждения элемент перемещается в системную корзину.

Перед переименованием и удалением расширение проверяет, что выбранный файл или папка не были заменены во время ввода или подтверждения. Если объект заменился, выберите его заново.

При Cut и Clear открытый сохранённый документ перемещается через VS Code, и его вкладка получает новый путь. Если файл открыли во время перемещения, исходник не удаляется; созданный файл назначения может остаться на месте, поэтому перед повтором проверьте обе директории.

Символические ссылки в деревьях скрыты; корень и служебные директории также должны быть обычными директориями. При переносе закрытого файла между файловыми системами он копируется без перезаписи, затем исходный файл удаляется. Если исходник изменился, появились несохранённые изменения или удалить его не удалось, созданная копия остаётся на месте. При ошибке переноса проверьте обе директории: файл назначения может быть неполным или уже существовать.

При выборе Copy или Cut расширение запоминает идентификаторы файла и сверяет их перед вставкой. Если идентификаторы изменились, выберите файл заново. Перед копированием сохраните изменения в исходном файле. Если несохранённые изменения появились во время копирования, исходный файл изменился на диске или проверить его не удалось, расширение предупреждает о возможной некорректной копии и сохраняет выбранный файл в буфере для повторной попытки.

Если исходное представление сменилось во время Copy или Cut, расширение сообщает об этом. При Cut исходник сохраняется, если удаление ещё не началось; копия в месте назначения может остаться. Перед повтором проверьте обе директории и выберите файл заново.

Команда **Clear** после подтверждения перемещает в `trash` файлы непосредственно из корня соответствующего представления. Она выбирает файлы с началом имени `YYYYMMDD-HHMMSS`, если дата в имени корректна и вместе со временем изменения не позднее указанной даты; вложенные папки не обходятся. Если файл не удалось проверить при составлении списка, очистка отменяется с сообщением об ошибке. Если файл изменился после составления списка, очистка пропускает его и сообщает об этом. При смене корня во время ввода или подтверждения операция отменяется; во время переноса оставшиеся файлы не обрабатываются, а начатое перемещение может завершиться. Удаление файлов и папок требует подтверждения и использует системную корзину.

После выбора даты и до ответа на подтверждение кандидаты на очистку отмечаются красным значком предупреждения в дереве соответствующего представления. Отметка показывает предварительный список: файлы с несохранёнными изменениями, конфликтами или ошибками могут быть пропущены. После ответа отметки исчезают.

## Разработка

```sh
npm ci
npm run compile
npm run lint
npm test
```

Для разработки нужен Node.js 22.13 или новее в ветке 22, либо Node.js 24 или новее. `npm test` предварительно запускает компиляцию и lint, затем запускает тесты в VS Code Extension Development Host через `@vscode/test-electron`: без открытого проекта, с тестовым workspace и при его повторном открытии с другой первой папкой. По умолчанию используется VS Code 1.105.0; при первом запуске он загружается. Для выбора другой версии задайте `SCRATCHES_VSCODE_VERSION`, а для использования установленного редактора — `SCRATCHES_VSCODE_EXECUTABLE` с путём к исполняемому файлу VS Code. Запуск настраивается в `scripts/run-tests.cjs`, тестовый runner — в `src/test/runner.ts`.

Тесты используют временный изолированный профиль VS Code, который удаляется после завершения. Чтобы проверить перенос между разными файловыми системами, задайте `SCRATCHES_TEST_CROSS_DEVICE_DIR` как путь к доступной для записи директории на другом томе. Без неё этот тест пропускается. CI настроен на Linux, macOS и Windows; некоторые тесты символических ссылок на Windows пропускаются, если система не разрешает их создание.

Карта устройства, точек изменения и ограничений находится в [EXTENSION_MAP.ru.md](EXTENSION_MAP.ru.md); английская версия для агентов — [EXTENSION_MAP.md](EXTENSION_MAP.md). Правила для агентов: [AGENTS.md](AGENTS.md), исходная русская версия: [AGENTS.ru.md](AGENTS.ru.md).
